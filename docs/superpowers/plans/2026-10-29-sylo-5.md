# Sylo 5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sylo 5.0.0 has one dashboard (V2). The classic EJS/htmx/Alpine dashboard and its code are removed. The release also carries the improvement list from 2026-10-28 (A2, B1–B3, C1, C2, D1–D3). D2 (Postal Pigeon) is built last.

**Architecture:** All work lands on the integration branch `v5` (created from `main` at v4.10.0). A draft PR `v5 → main` stays open so `test.yml` runs on every push. Nothing is merged to `main` and nothing is released until the owner says so. Patch releases for 4.10.x can still go out from `main` meanwhile. At merge time the squash title must carry `feat!:` plus a `BREAKING CHANGE:` footer so release-please bumps to 5.0.0.

**Tech Stack:** Node 22 (ESM), Express, EJS (public pages only after 5.0), React 19 + Vite 8 (`web-v2/`), `node --test`, SQLite + Postgres, Swift (`apps/sylo-ios`).

**Spec:** Obsidian `Planer/Sylo/Plan – Utfasing av klassisk dashboard.md` (phase 2 + 3) and `Planer/Sylo/Plan – Forbedringer (2026-10-28).md` (A2, B1, B2, B3, C1, C2, D1, D2, D3). Code facts gathered 2026-10-29 at v4.10.0 are cited as `path:line` below; re-check line numbers before editing, they drift.

## Global Constraints

- Branch `v5` only. Never push to `main`, never merge the draft PR, never merge a release PR, never deploy to the VPS. Owner tests on sylo-test (Tower, port 3010) first.
- Every DB change goes in both places: SQLite migration in `src/db/index.js` and the Postgres bootstrap/migration, plus `GUILD_TABLES` when per-guild. Migrations are forward-only.
- The JSON shape of `GET/POST /api/v2/guilds/:id/modules/<id>/config` must not change in a way that breaks `apps/sylo-ios` (it reads the same responses). Adding fields is fine; renaming or removing is not.
- Keep `/health` JSON, `/metrics`, `/roadmap/posts.json`, `/auth/*`, `/api/mobile/*`, `/api/push-relay/*`, `/webhooks/github/*`, `/api/v2/*` and the public pages (`/verify/:guild`, `/appeal/:guild`, `/leaderboard/:guild`, `/lb/:slug`, `/auth/login`, `/auth/mobile/confirm`) working.
- Old classic URLs (in Discord messages and bookmarks) must keep working through permanent redirects.
- Every timer keeps `.unref()` (tests are `node --test` per-file processes).
- Tests: `npm test` (SQLite) and the Postgres leg run in CI. Heavy local runs go to LANBox Docker (`--context unraid`), never Docker Desktop, never Tower.
- No new runtime dependency without a line in the task report saying why. Dev dependencies for Vitest are allowed (Task 1).
- Commits: Conventional Commits. No Co-Authored-By or attribution lines. Breaking commits use `feat!:`/`fix!:` or a `BREAKING CHANGE:` footer.

## Review Focus

1. A Discord message from 4.x with a classic link (`/guilds/<key>/tickets/<id>`, `/guilds/<key>/appeals`, `/guilds/<key>/m/<id>`, `/roadmap`) still lands on the matching V2 page after 5.0. Test owner: Task 4.
2. Open mode (no login configured) still serves V2 and the public pages; nothing tries to render the deleted `partials/header.ejs`, including the `error` view from every caller. Test owner: Tasks 3 and 4.
3. A self-hoster who never set `SESSION_SECRET` keeps their sessions and verify/appeal links across a restart. Test owner: Task 5.
4. The enforcing CSP does not break: V2 boot (theme script), `/telemetry.js` with Sentry DSN and Keen Kestrel configured, Turnstile on `/verify`, admin-entered embed image URLs, leaderboard bars. Test owner: Task 7.
5. Graceful shutdown after B2 does not double-post: a module tick that is running when SIGTERM arrives is not started again, and no timer keeps the process alive. Test owner: Task 6.
