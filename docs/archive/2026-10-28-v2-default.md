# Dashboard V2 becomes the default (phase 1 of retiring the classic dashboard) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every user lands in Dashboard V2, including in open mode. The classic dashboard stays reachable for one release behind `/?classic=1` with a retirement banner. Every V2 page works without falling back to classic routes.

**Architecture:**
- Fill the remaining gaps in V2 (React app under `web-v2/`, API in `src/web/routes/v2Api.js`, `v2Staff.js` and `v2GuildData.js`).
- Make `/` and the classic page URLs redirect into `/v2`.
- Point the links the bot sends at V2 paths.
- Nothing classic is deleted in this phase; that is phase 2 (5.0.0).

**Tech Stack:** Node 22 ESM, Express 5, EJS (public pages only), React 19 and react-router 7 and Vite 8 (web-v2), `node --test`, SQLite and Postgres.

**Spec:** the owner-approved plan `Planer/Sylo/Plan – Utfasing av klassisk dashboard.md` (Obsidian, Norwegian). Its decisions are binding:
- B1: `/stats` becomes an owner-only V2 page.
- B2: `/commands` becomes a public V2 page.
- B3: the roadmap is publicly viewable in V2; voting and suggesting need login.
- B4: this phase ships as 4.10.0 (`feat:` commits).
- B5: classic stays one release behind a banner.

Code map: `E:\Obsidian\Sylo\Kodekart\Sylo\` (start at `00 Sylo – oversikt.md`, then `07 Web og API.md` and `08 Moduler.md`).

## Global Constraints

- Follow `CONTRIBUTING.md`: ESM, no new runtime dependencies, Prettier (single quotes, semicolons, printWidth 110, es5 trailing commas), `npm test`, `npm run lint` and `npm run format:check` green. Tests must pass on both SQLite and Postgres CI legs.
- Use `guildKey()`, never `guild.id`, in bot and module code. Guild ids in URLs may be `fluxer:<id>`; web-v2 validates them with `gid()`.
- **Auth and security:**
  - New `/api/v2` endpoints use the same guards as their neighbours: `requireGuildAdmin`, staff-aware ticket access, `requireOwner`.
  - CSRF is the `x-csrf-token` header. Rate limits mirror the classic route being replaced.
  - App bearer tokens keep working on `/api/v2/*`.
  - **Public endpoints (commands list, roadmap read) expose nothing more than the public classic pages do today.**
- **Classic is untouched except:** the redirects (Task 5), the banner (Task 5), and moving shared helpers out of `routes/roadmap.js` (Task 3). Classic tests keep passing.
- **Do not deploy** to the VPS or touch production. The owner deploys Sylo themselves.
- Conventional Commits with human-readable subjects, because each becomes a changelog bullet. No Co-Authored-By or attribution lines.

## Review Focus

1. **Open mode** (no OAuth configured, synthetic "local admin"): V2 must load, list guilds and save settings. It has never been the default there.
2. **Old links** in Discord messages and docs (`/guilds/<key>/tickets/<id>`, `/guilds/<key>/appeals`, `/guilds/<key>/m/<module>`, `/account`, `/settings`, `/health` HTML, `/stats`, `/commands`) must land on the matching V2 page. With `?classic=1` active, they must still reach classic.
3. **Fluxer guild keys** (`fluxer:123…`) in every new route and redirect: encode and decode them correctly.
4. **Public pages** (commands, roadmap) must work without a session and must not leak guild or user data.
5. **An owner-only page** (Stats) must answer 403 for non-owners on both the API and the page.
